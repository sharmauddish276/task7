# Assignment 7: Identifying APIs for a To-Do List App

## 1. Introduction
This document plans the APIs needed by a simple To-Do List app. An API helps the React frontend communicate with the backend. The app can add, display, edit, complete, and delete tasks.

**This assignment is API planning only. No backend implementation is required.**

## 2. Basic API details
- Base URL (example): `https://api.example.com`
- Resource: `tasks`
- Data format: JSON
- Header: `Content-Type: application/json`
- Task fields: `id`, `title`, `description`, `completed`, `createdAt`, `updatedAt`

## 3. API endpoints

### Add a task
- **Method:** `POST`
- **URL:** `/api/tasks`
- **Request body:**
```json
{"title":"Complete homework","description":"Finish math questions"}
```
- **Example response:**
```json
{"id":"task_101","title":"Complete homework","description":"Finish math questions","completed":false,"createdAt":"2026-11-10T10:00:00Z"}
```
- **Reason:** POST creates a new task. The server validates the title, generates a unique ID, sets completed to false, saves the task, and returns it.

### Get all tasks
- **Method:** `GET`
- **URL:** `/api/tasks`
- **Request body:** None. Optional filter: `/api/tasks?completed=false`
- **Example response:**
```json
[{"id":"task_101","title":"Complete homework","description":"Finish math questions","completed":false}]
```
- **Reason:** GET reads all tasks. A filter can show only completed or incomplete tasks.

### Get one task
- **Method:** `GET`
- **URL:** `/api/tasks/{id}`
- **Request body:** None. Example: `/api/tasks/task_101`
- **Example response:**
```json
{"id":"task_101","title":"Complete homework","description":"Finish math questions","completed":false}
```
- **Reason:** Finds one task using its unique ID.

### Update task details
- **Method:** `PUT`
- **URL:** `/api/tasks/{id}`
- **Request body:**
```json
{"title":"Complete science homework","description":"Read chapter 2"}
```
- **Example response:**
```json
{"id":"task_101","title":"Complete science homework","description":"Read chapter 2","completed":false,"updatedAt":"2026-11-10T11:00:00Z"}
```
- **Reason:** PUT updates the task details after checking that the ID exists.

### Mark complete or incomplete
- **Method:** `PATCH`
- **URL:** `/api/tasks/{id}/status`
- **Request body:**
```json
{"completed":true}
```
- **Example response:**
```json
{"id":"task_101","title":"Complete homework","completed":true}
```
- **Reason:** PATCH changes only the completion status. Use `false` to mark it incomplete again.

### Delete a task
- **Method:** `DELETE`
- **URL:** `/api/tasks/{id}`
- **Request body:** None. Example: `/api/tasks/task_101`
- **Example response:**
```json
{"message":"Task deleted successfully","id":"task_101"}
```
- **Reason:** Deletes the task with the given ID.

## 4. Unique task ID
When a task is created, the server can generate a UUID or use an ID generated by the database. Every task must have a different ID so the correct task can be updated or deleted. Example: `task_101`.

## 5. Common status codes
- `200 OK`: Request successful.
- `201 Created`: Task created.
- `400 Bad Request`: Required information is missing or invalid.
- `404 Not Found`: Task ID does not exist.
- `500 Internal Server Error`: Unexpected server problem.

## 6. CRUD operations
- **Create:** `POST /api/tasks`
- **Read:** `GET /api/tasks` and `GET /api/tasks/{id}`
- **Update:** `PUT /api/tasks/{id}` and `PATCH /api/tasks/{id}/status`
- **Delete:** `DELETE /api/tasks/{id}`

## 7. Possible challenges and solutions
- **Duplicate IDs:** Generate IDs using UUID or the database.
- **Empty title:** Validate on the server and return 400.
- **Missing task:** Return 404 if the ID is not found.
- **Network error:** Show a friendly message and allow retry.
- **Multiple users editing:** Use login/authentication and update timestamps in a larger app.
- **Accidental deletion:** Ask for confirmation before sending DELETE.

## 8. Conclusion
These endpoints provide the main To-Do List features. POST creates, GET reads, PUT/PATCH updates, and DELETE removes tasks. Together they cover CRUD operations and can later be connected to a React frontend and backend database.
